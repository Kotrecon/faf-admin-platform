# Требования к универсальной админ-панели

**Версия:** 0.2  
**Дата:** 2026-09-20  
**Статус:** Прототип

---

## 1. Общее описание

| Поле                 | Значение                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------ |
| **Что это**          | Универсальный шаблон админ-панели для управления множеством сервисов                       |
| **Зачем**            | Единый frontend для всех сервисов, быстрое добавление новых сервисов без переделки админки |
| **Для кого**         | Внутренние пользователи: Admin, SecurityAdmin, ContentManager                              |
| **Сколько сервисов** | Сейчас 13, архитектура масштабируема на N сервисов                                         |
| **Статус**           | Прототип, бэкенды сервисов без контроллеров администрирования — делаем с нуля              |

---

## 2. Архитектура

```bash
┌─────────────────────────────────────────────────────────┐
│              Admin Frontend (SPA)                       │
│  • Один файл / приложение                               │
│  • Работает с любым сервисом через generic API          │
│  • Роутинг: ?service={id}&page={dashboard|users|...}    │
└─────────────────────────────────────────────────────────┘
                          │
        ┌─────────────────┼─────────────────┐
        ▼                 ▼                 ▼
   Service 1         Service 2         Service N
   (.NET 10 API)    (.NET 10 API)    (.NET 10 API)
   • Generic admin  • Generic admin  • Generic admin
     controller       controller       controller
   • EF Core + PG   • EF Core + PG   • EF Core + PG
   • JWT auth       • JWT auth       • JWT auth
   • Audit log      • Audit log      • Audit log
```

| Компонент             | Технология                             | Примечание                              |
| --------------------- | -------------------------------------- | --------------------------------------- |
| Frontend              | Чистый JS + CSS (или легкий фреймворк) | Одно приложение на все сервисы          |
| Backend               | .NET 10 + EF Core + PostgreSQL         | Generic controller в shared project     |
| Auth                  | ASP.NET Identity + JWT                 | 3 роли, токены в localStorage           |
| Shared                | Rate limiting, caching, routing        | В общем проекте для всех сервисов       |
| Gateway (опционально) | Простой сервис-роутер                  | Единая точка входа, упрощение навигации |

## 3. Навигация

### Выбранный вариант: **A** (Sidebar = сервисы, Top tabs = страницы)

```bash
┌────────────┬──────────────────────────────────────────┐
│  SIDEBAR   │  TOP TABS                                │
│  Сервис 1  │  [Dashboard] [Users] [Settings] [Logs]   │
│  Сервис 2  │  ─────────────────────────────────────   │
│  Сервис 3  │  MAIN CONTENT                            │
│  ...       │  (контент выбранной страницы)            │
│  Сервис 13 │                                          │
└────────────┴──────────────────────────────────────────┘
```

**URL формат:**

```bash
admin.html?service=1&page=dashboard
admin.html?service=1&page=users
admin.html?service=2&page=settings
```

**Страницы внутри сервиса (предварительно):**

- `dashboard` — KPI, графики, метрики сервиса
- `users` — управление пользователями сервиса (CRUD)
- `settings` — настройки сервиса
- `logs` — логи и audit
- `...` — другие страницы по необходимости

**Sidebar:**

- Список всех сервисов (13 сейчас, расширяемо)
- Активный сервис выделен
- Клик переключает сервис (сохраняя текущую страницу или сбрасывая на dashboard)

**Top tabs:**

- Список страниц текущего сервиса
- Активный таб выделен
- Клик переключает страницу

## 4. Дашборд (универсальный, под сервис)

| Требование          | Детали                                                                   |
| ------------------- | ------------------------------------------------------------------------ |
| **Что это**         | Страница с метриками и графиками конкретного сервиса                     |
| **KPI-карточки**    | N карточек (динамически, сколько нужно сервису)                          |
| **Графики**         | 1+ график (динамически)                                                  |
| **Универсальность** | Одинаковая структура для всех сервисов, данные подставляются динамически |

**Предварительные метрики (обсуждается):**

- Сервис инфо (название, версия, статус)
- Загрузка CPU
- Алерты (количество, последние)
- Пользователи (активные, всего)
- БД (размер, подключения, запросы/сек)
- Другие метрики по необходимости

**Требует уточнения:**

- Какие именно метрики для каждого сервиса
- Период обновления (real-time, polling, manual)
- Источники данных (сами сервисы, мониторинг, БД)

## 6. Авторизация и роли

| Требование                     | Детали                                                   |
| ------------------------------ | -------------------------------------------------------- |
| **Auth provider**              | ASP.NET Identity (встроенный)                            |
| **Тип токена**                 | JWT                                                      |
| **Передача токена**            | `Authorization: Bearer {token}` в каждом запросе к API   |
| **Хранение токена (frontend)** | `localStorage` (вариант A, для прототипа)                |
| **Время жизни токена**         | 60 минут                                                 |
| **Refresh token**              | Есть, с flow обновления                                  |
| **Logout**                     | Удаление токена на клиенте (без blacklist)               |
| **Роли (RBAC)**                | 3 роли: `Admin`, `SecurityAdmin`, `ContentManager`       |
| **Роли в claims**              | Да, поле `role` в JWT payload                            |
| **Доступ к `/api/admin/*`**    | Только авторизованные пользователи с одной из 3 ролей    |
| **Gateway**                    | Нет (Rate limiting, caching, routing — в shared project) |

## 7. Валидация данных

| Требование                 | Детали                                                                                          |
| -------------------------- | ----------------------------------------------------------------------------------------------- |
| Frontend валидация         | Только ввод: формат email, required, длина, простые паттерны (браузерные HTML5 validation + JS) |
| Backend валидация          | Вся бизнес-валидация: уникальность, права, сложные правила, валидация сущности                  |
| Разделение ответственности | Frontend — UX (быстрая обратная связь), Backend — надёжность и бизнес-правила                   |
| Дублирование               | Нет (frontend — формат, backend — смысл)                                                        |
| Формат ошибок backend      | Стандартизированный: { errors: { field: ["ошибка 1", "ошибка 2"] } }                            |
| Отображение ошибок         | Под полями формы + общий список в модалке                                                       |
| Библиотека backend         | Data Annotations или FluentValidation (.NET) — по ситуации                                      |
| Расширяемость              | В будущем можно добавить JSON Schema для генерации валидации на frontend                        |

## 8. Поиск

| Требование                | Детали                                                      |
| ------------------------- | ----------------------------------------------------------- |
| Тип поиска                | Частичное совпадение (LIKE '%query%')                       |
| Поля поиска               | Зависит от сущности (настраивается на бэкенде)              |
| Регистронезависимый       | Да                                                          |
| Минимальная длина         | 2-3 символа (конфигурируемо)                                |
| Пустой поиск              | Возвращает все записи (с учётом фильтров)                   |
| Параметр API              | ?search={query}                                             |
| Full-text search          | Нет (можно добавить в будущем)                              |
| Поиск по нескольким полям | Нет (пока только одно основное поле, потом можно расширить) |
| Защита от injection       | Параметризованные запросы (EF Core)                         |

## 15. KPI-метрики (финальная версия)

### 1. Универсальный дашборд (по каждому сервису)

| Метрика                           | Тип                           | Источник                    |
| --------------------------------- | ----------------------------- | --------------------------- |
| **Загрузка CPU**                  | %                             | Observability слой          |
| **Использование памяти**          | MB / %                        | Observability слой          |
| **Статус сервиса**                | Online / Offline / Degraded   | Health check endpoint       |
| **Количество алертов**            | Критичные / Предупреждения    | Alerting система            |
| **БД: размер**                    | GB                            | PostgreSQL статистика       |
| **БД: подключения**               | Количество активных           | PostgreSQL pg_stat_activity |
| **БД: запросы/сек**               | Количество                    | PostgreSQL статистика       |
| **Рейтлимиты: по сервису**        | Лимиты, текущее использование | Rate limiting слой          |
| **Resilience: запросы к сервису** | Всего / удачные / неудачные   | Observability слой          |

**Графики:**

- CPU Load (24h / 7d)
- Memory Usage (24h / 7d)
- DB Queries/sec (24h)
- Requests: success/fail (24h / 7d)

### 2. Системный дашборд (единый, страница "Пользователи системы")

| Метрика                            | Тип                                 | Источник                                 |
| ---------------------------------- | ----------------------------------- | ---------------------------------------- |
| **Пользователи: активные**         | Количество                          | БД пользователей                         |
| **Пользователи: всего**            | Количество                          | БД пользователей                         |
| **Пользователи: новые за период**  | Количество                          | БД пользователей (filter by createdAt)   |
| **Токены: потрачено (по системе)** | Количество                          | Счётчик использования API                |
| **Модели ИИ: по системе**          | 3-5 моделей, usage                  | Статистика по моделям (агрегированная)   |
| **Модели ИИ: по пользователю**     | Предпочтения пользователя (топ-3/5) | Статистика использования на пользователя |

**Графики:**

- Token usage (7d / 30d)
- New users (7d / 30d)
- AI models usage distribution (по системе)
- AI models per user (предпочтения)
